スタックちゃんに話しかけると返事が返ってくる。ネットが無い場所では **iPad
が頭**になり、Wi-Fi につながっていれば **iPad なしでも単独で** Cloudflare の AI
を使って話せる。自宅では Home Assistant とも話せる。
スタックちゃんの挙動の一部は **Ruby で書いて Wasm にし、iPad から書き込める**。
これがこのプロジェクトのゴール。

## リポジトリの構成

| ディレクトリ | 中身                                                                                         |
| ------------ | -------------------------------------------------------------------------------------------- |
| `web/`       | このサイト (Markdown → GitHub Pages)。単独モードで使う Cloudflare Worker もここに足す        |
| `ios/`       | iPad アプリ。STT / TTS / ローカル LLM、Ruby → Wasm、スタックちゃんへのアップロード、各種設定 |
| `m5/`        | ファームウェア。Wasm ランタイム、Wasm と画像を更新する API、Wi-Fi、単独モードの会話          |

## ハードウェア

M5Stack 公式の **StackChan (SKU: K151)**。

- 本体: CoreS3 (ESP32-S3)、2.0 インチのタッチ画面 (顔)
- マイク 2 つ、1 W スピーカー、カメラ (0.3 MP)、9 軸 IMU、近接・照度センサ、
  microSD
- 胴体: サーボ 2 つ (左右は 360° 連続回転、上下は 90°)、RGB LED、赤外線、 3
  ゾーンのタッチ、NFC、バッテリー
- 出荷時のファームウェア (AI エージェント入り) は使わず、`m5/`
  の自作ファームウェアに焼き替える

マイクは **M5 のもの**を使う。iPad のマイクは使わない。

## 役割分担

**スタックちゃん (M5) は「体」。頭は、つながり方によって iPad か Cloudflare。**

M5 は小さなマイコンなので、音声認識・音声合成・LLM は載せない。M5 がやるのは、耳
(マイク)・口 (スピーカー)・顔 (画面)・首 (サーボ)
と、それを動かす小さなプログラム (Wasm) の実行、そして「頭」との音声の
やり取り。

### スタックちゃん (M5) がやること

- 顔 (アバター) の表示、表情・口パク・まばたき
- マイクの音を頭 (iPad か Cloudflare) へ送り、返ってきた音声を鳴らす
- サーボで首を動かす
- 「右を向いて」「うなずいて」のような決まった命令は、自分で聞き取ってその場で実行する
  (KoeAct-JP。iPad もネットも要らない。[音声の命令](./m5-firmware#音声の命令-))
- **Wasm ランタイム**を持ち、アップロードされた Wasm で挙動を制御する
- **画像** (表情の差し替え、アイコンなど) を受け取って保存・表示する
- Wi-Fi: 自分がアクセスポイントになる (AP)、周りの Wi-Fi を探す、Wi-Fi につなぐ
  (STA)
- 単独モードで Cloudflare の Worker と、自宅では Home Assistant と直接話す
- 上記を操作する **HTTP / WebSocket API**。使えるのは最初にペアリングした
  アプリだけ ([認証](#m5-の-api-の認証))

M5 に入れるのは Wasm の**ランタイムだけ**。Ruby 処理系は M5 には載せない (Ruby →
Wasm の変換は iPad でやる)。

### iPad がやること

- AP モードでの**頭**: STT / ローカル LLM / TTS をすべてオンデバイスで
- **Ruby → Wasm** の変換と、スタックちゃんへのアップロード
- 画像のアップロード
- 設定: スタックちゃんの Wi-Fi (SSID 選択・パスワード入力)、Cloudflare Worker の
  URL と鍵、Home Assistant の URL とトークン。これらは M5 に書き込み、単独
  モードで M5 が自分で使う

### Cloudflare がやること

- Wi-Fi につながったときの**頭**: 自分の Worker が Workers AI の STT / LLM / TTS
  を呼ぶ
- Workers AI の API トークンは Worker に置く。M5 や iPad には置かない

## つながり方 — 2 つのモード

**M5 が AP のときは iPad が必須。AP でないとき (Wi-Fi につながっているとき)
は、基本的に iPad なしで動く。**

| モード    | M5 の Wi-Fi               | 頭                     | iPad                         |
| --------- | ------------------------- | ---------------------- | ---------------------------- |
| 直結      | AP (`stackchan-XXXX`)     | iPad (オンデバイス)    | 必須                         |
| 単独      | STA (家などの Wi-Fi)      | Cloudflare Worker      | 不要。あれば設定・書き込み用 |
| 単独+自宅 | STA (Home Assistant あり) | Cloudflare Worker + HA | 不要                         |

### 直結モード (スタックちゃんが AP)

最初の、そして最低限のモード。ネットが無くても動く。

```
┌──────────────┐  Wi-Fi (AP: stackchan-XXXX)  ┌─────────────┐
│ スタックちゃん │◀────────────────────────────▶│    iPad     │
│     (M5)     │  HTTP / WebSocket 192.168.4.1 │ STT/LLM/TTS │
└──────────────┘                               └─────────────┘
```

1. 保存済みの Wi-Fi が無い (またはつながらない) とき、スタックちゃんは AP
   `stackchan-XXXX` を立てる。パスワードは画面に表示 (QR コードでも出す)。
2. iPad をその Wi-Fi につなぐ (アプリから `NEHotspotConfiguration`
   で接続させてもよい)。
3. 初回はペアリングして共有鍵を作る ([認証](#m5-の-api-の認証))。
4. 話しかける → M5 のマイク音声を iPad へ → STT → ローカル LLM → TTS → 音声を M5
   へ → スタックちゃんが口パクしながらしゃべる。

この間 iPad はインターネットにつながらない (セルラー版を除く)
ので、応答はローカル LLM だけで作る。

### Wi-Fi 設定 (直結 → 単独)

1. 直結モードで、iPad アプリから「Wi-Fi 設定」を開く。
2. スタックちゃんが周りの Wi-Fi をスキャンし (AP を立てたまま STA
   でスキャン)、一覧を iPad に返す。
3. iPad の画面で SSID を選び、パスワードを入力して送る (共有鍵で暗号化)。
   Cloudflare Worker と Home Assistant の設定もこのとき一緒に送れる。
4. スタックちゃんがその Wi-Fi につなぐ。成功したら設定を保存し、AP を止める。
5. 以降は起動すると保存した Wi-Fi につなぎ、単独モードで動く。iPad も同じ Wi-Fi
   にいれば、mDNS (`stackchan.local`, `_stackchan._tcp`)
   で見つけて設定や書き込みができる。

### 単独モード (iPad なし)

```
┌──────────────┐  WebSocket (wss)  ┌───────────────────┐
│ スタックちゃん │◀────────────────▶│ Cloudflare Worker  │──▶ Workers AI
│     (M5)     │   音声 / 制御     │ STT → LLM → TTS    │    (STT/LLM/TTS)
└──────┬───────┘                   └───────────────────┘
       │ REST (LAN 内)
       ▼
 Home Assistant (自宅のみ)
```

- M5 が Worker に WebSocket でつなぎ、マイクの音声を送る。Worker が STT → LLM →
  TTS をして、音声と表情などの制御メッセージを返す。
- Worker への認証は、iPad が設定時に書き込んだデバイス用の鍵で行う。
- ネットが落ちたら画面で知らせる。iPad が同じ Wi-Fi にいれば、iPad
  を頭にして話を続けられる (直結モードと同じ流れ)。

### 自宅 (単独モード + Home Assistant)

- 「電気消して」「リビングの温度は?」→ Worker の LLM が HA の操作を **tool
  call** として M5 に返す → **M5 が LAN 内の HA の API を呼ぶ** → 結果を Worker
  に返す → 返事をしゃべる。
- HA を外に公開しなくて済むよう、HA を呼ぶのは Worker ではなく M5。
- HA のアクセストークンは iPad が設定時に M5 に書き込む。LLM に触らせる
  エンティティは設定で絞る。
- 自宅かどうかは「HA に届くか」で判定する (SSID だけに頼らない)。
- HA 側の出来事 (来客、洗濯終了など) を HA の WebSocket で受けて、
  スタックちゃんが知らせる。

## 会話の流れ

```
                    ┌── 直結: iPad (SpeechAnalyzer → Foundation Models → AVSpeechSynthesizer)
[M5 マイク] ─PCM─▶ 頭 ┤
                    └── 単独: Cloudflare Worker (Workers AI の STT → LLM → TTS)
                                         │ tool call (自宅のみ)
                                         ▼
                                   M5 → Home Assistant
頭 ─PCM + 制御─▶ [M5 スピーカー・顔・首]
```

- 発話区間の検出: 最初は画面/胴体のタッチで「押して話す」。慣れたら VAD
  (無音検出) で自動化する。
- 音声フォーマット: 16 kHz / 16 bit / モノラル PCM を WebSocket
  のバイナリフレームで送る。帯域が問題になったら Opus を検討する。
- しゃべっている間は M5 が音量から口パクを作る。表情は LLM の応答に付けた タグ
  (例: `[happy]`) か、Wasm 側のロジックで決める。
- 頭が iPad でも Cloudflare でも、M5 から見たプロトコルは同じにする。

## M5 の API の認証

**M5 の API を使えるのは、最初にハンドシェイクしたアプリだけ。** 両者が共有鍵を
持ち、以降のやり取りをその鍵で認証する。

1. ペアリングされていない M5 に iPad アプリがつなぐと、鍵交換 (X25519 の ECDH)
   をする。
2. 両者が同じ 6 桁の確認コードを表示し、ユーザーが一致を確認して M5
   のタッチで承認する (盗聴・なりすまし対策)。
3. できた共有鍵を M5 は NVS に、iPad は Keychain に保存する。M5
   はこれ以降、新しいペアリングを受け付けない。
4. HTTP のリクエストは共有鍵の HMAC で署名し、Wi-Fi のパスワードや各種
   トークンなどの秘密は共有鍵で暗号化して送る。
5. 別のアプリ・端末に替えるときは、M5 の本体操作 (長押しなど) で
   ペアリングを消してからやり直す。

詳しくは [M5 ファームウェア](./m5-firmware#api-の認証)。

## Wasm でスタックちゃんの挙動を制御する

スタックちゃんの「性格」や「しぐさ」を、ファームウェアを焼き直さずに変えたい。
そのために M5 に Wasm ランタイムを入れ、挙動の一部を Wasm に任せる。

- M5 は **ホスト関数** (顔を変える、首を動かす、画像を出す、しゃべる、ログ…) を
  Wasm に公開する。
- Wasm は `init` / `on_tick` / `on_event` (タッチ、ボタン、発話開始/終了、
  受け取ったテキストなど) を export する。
- Wasm と画像は **HTTP API でアップロード**して差し替えられる。
- 不正な Wasm で起動不能にならないよう、前のバージョンを残してロールバック
  できるようにする。
- ランタイムは **WAMR** (WebAssembly Micro Runtime)。Bytecode Alliance
  が開発を続けていて、ESP-IDF を公式にサポートしている。

API と ABI の詳細は [M5 ファームウェア](./m5-firmware) に書く。

### Ruby → Wasm

挙動は Ruby で書きたい。ただし CRuby を丸ごと Wasm にした ruby.wasm は数 MB
あり、M5 のメモリには載らない。そこで組み込み向けの小さな Ruby (mruby/c /
PicoRuby 系) を使う。

1. **VM の Wasm** (mruby/c 系 VM + スタックちゃん用ホスト関数のバインディング)
   を事前にビルドしておく。数百 KB 以下を目標にする。
2. iPad 上で Ruby ソースを **バイトコード (`.mrb`) にコンパイル**する。
   コンパイラ自体も Wasm にして iPad アプリ内の Wasm ランタイムで動かす。
3. VM の Wasm にバイトコードを埋め込んで **1 つの `behavior.wasm`** にする。
4. スタックちゃんへアップロードする。

M5 から見ればただの Wasm なので、Ruby 以外 (Rust、Zig、AssemblyScript など)
で書いた Wasm も同じ API に載る。詳細は [iPad アプリ](./ios-app)。

## Cloudflare Worker

- 単独モードの頭。M5 からの WebSocket を受け、Workers AI の STT / LLM / TTS
  を呼ぶ。会話の履歴も Worker 側 (Durable Object) で持つ。
- Workers AI の API トークンは Worker に置く。M5 は設定時に書き込まれた
  デバイス用の鍵で Worker に認証する。
- AI Gateway を挟んで、ログ・キャッシュ・レート制限をかける。
- コードは `web/` 側 (Deno + Remix テンプレートの Cloudflare Workers 構成)
  に足す。

## 段階的な作り方

| フェーズ | ゴール                                                                                                                              |
| -------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| 0        | リポジトリ、構想ドキュメント (この文書)                                                                                             |
| 1        | M5 が AP を立て、iPad とペアリングする。話しかけるとローカルだけで返事が来る (実装済み、実機で確認済み)                             |
| 2        | M5 に Wasm ランタイム。Wasm と画像を API でアップロードして挙動が変わる                                                             |
| 3        | iPad で Ruby → Wasm を作ってアップロードできる                                                                                      |
| 4        | Wi-Fi 設定 (スキャン → 選択 → 接続)。Cloudflare Worker で単独モード (Wi-Fi 設定と、同じ Wi-Fi の iPad が頭になるところまで実装済み) |
| 5        | Home Assistant 連携                                                                                                                 |

フェーズ 1 が「最低限の機能」。ここまでで、ネットの無い場所でも
スタックちゃんと話せる。フェーズ 4 で iPad なしでも話せるようになる。

## 決めたこと

- 機種は StackChan (K151)。マイクは M5 のもの
- M5 の API は最初にハンドシェイクしたアプリとだけ共有鍵を持つ
- Wasm ランタイムは WAMR
- 単独モードを作る。M5 が AP でないときは、基本 iPad なしで動く
- 決まった命令 (向く、うなずく、表情、LED、音量、明るさ) は M5 の中の KoeAct-JP
  で聞き取る

## 未決事項

- Cloudflare 側で使うモデル (STT / LLM / TTS)。
- 単独モードでネットが落ちたときの振る舞い (画面表示だけか、iPad
  を探しに行くか)。
- ペアリングを消す本体操作の具体的な形。
