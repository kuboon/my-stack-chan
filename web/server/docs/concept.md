スタックちゃん (M5Stack) に話しかけると、**iPad 経由で返事が返ってくる**。
ネットが無くても最低限は動き、ネットがあれば Cloudflare の AI
でより賢く、自宅では Home Assistant とも話せる。スタックちゃんの挙動の一部は
**Ruby で書いて Wasm にし、iPad から書き込める**。これがこのプロジェクトの
ゴール。

## リポジトリの構成

| ディレクトリ | 中身                                                                                |
| ------------ | ----------------------------------------------------------------------------------- |
| `web/`       | このサイト。構想・設計ドキュメントを Markdown で書き、GitHub Pages に出す           |
| `ios/`       | iPad アプリ。STT / TTS / ローカル LLM、Ruby → Wasm、スタックちゃんへのアップロード  |
| `m5/`        | M5Stack ファームウェア。Wasm ランタイム、Wasm と画像を更新する HTTP API、Wi-Fi 制御 |

## 役割分担

**スタックちゃん (M5) は「体」、iPad は「頭」。**

M5 は小さなマイコンなので、音声認識・音声合成・LLM は載せない。M5 がやるのは、耳
(マイク)・口 (スピーカー)・顔 (画面)・首 (サーボ)
と、それを動かす小さなプログラム (Wasm) の実行だけ。考えるのは iPad。

### スタックちゃん (M5) がやること

- 顔 (アバター) の表示、表情・口パク・まばたき
- マイクの音を iPad へ送る / iPad から来た音声を鳴らす
- サーボで首を動かす
- **Wasm ランタイム**を持ち、アップロードされた Wasm で挙動を制御する
- **画像** (表情の差し替え、アイコンなど) を受け取って保存・表示する
- Wi-Fi: 自分がアクセスポイントになる (AP)、周りの Wi-Fi を探す、Wi-Fi につなぐ
  (STA)
- 上記を操作する **HTTP / WebSocket API**

M5 に入れるのは Wasm の**ランタイムだけ**。Ruby 処理系は M5 には載せない (Ruby →
Wasm の変換は iPad でやる)。

### iPad がやること

- **STT** (音声 → テキスト) — オンデバイス
- **ローカル LLM** — オンデバイスで応答を作る
- **TTS** (テキスト → 音声) — オンデバイス
- **Ruby → Wasm** の変換と、スタックちゃんへのアップロード
- 画像のアップロード
- スタックちゃんの Wi-Fi 設定 (SSID 選択・パスワード入力)
- ネットがあるとき: Cloudflare の AI API を呼ぶ
- 自宅にいるとき: Home Assistant と連携

## つながり方 — 3 つのモード

### モード 1: 直結 (スタックちゃんが AP)

最初の、そして最低限のモード。ネットが無くても動く。

```
┌────────────┐   Wi-Fi (AP: stackchan-XXXX)   ┌──────────┐
│ スタックちゃん│◀──────────────────────────────▶│   iPad   │
│    (M5)    │   HTTP / WebSocket 192.168.4.1  │ STT/LLM/TTS│
└────────────┘                                 └──────────┘
```

1. スタックちゃんが起動すると AP `stackchan-XXXX` を立てる。パスワードは画面に
   表示 (QR コードでも出す)。
2. iPad をその Wi-Fi につなぐ (アプリから `NEHotspotConfiguration`
   で接続させてもよい)。
3. iPad アプリが `192.168.4.1` の API と WebSocket につなぐ。
4. 話しかける → M5 のマイク音声を iPad へ → STT → ローカル LLM → TTS → 音声を M5
   へ → スタックちゃんが口パクしながらしゃべる。

この間 iPad はインターネットにつながらない (セルラー版を除く)
ので、応答はローカル LLM だけで作る。

### モード 2: 同じ Wi-Fi (ネットあり)

1. モード 1 の状態で、iPad アプリから「Wi-Fi 設定」を開く。
2. スタックちゃんが周りの Wi-Fi をスキャンし (AP を立てたまま STA
   でスキャン)、一覧を iPad に返す。
3. iPad の画面で SSID を選び、パスワードを入力して送る。
4. スタックちゃんがその Wi-Fi につなぐ。成功したら設定を保存し、AP を止める。
5. iPad も同じ Wi-Fi につなぎ直す。スタックちゃんは mDNS (`stackchan.local`,
   `_stackchan._tcp`) で自分を知らせ、iPad が見つけて再接続する。

ネットがつながるので、iPad は **Cloudflare の AI API** を使って、より高度な
応答ができる。ローカル LLM は、ネットが落ちたときや速さが欲しいときの
フォールバックとして残す。

### モード 3: 自宅 (ネットあり + Home Assistant)

モード 2 の特別な場合。自宅の Wi-Fi にいて Home Assistant (HA) に届くときは、HA
と やり取りする機能を有効にする。

- 「電気消して」「リビングの温度は?」→ LLM が HA の操作 (tool call) に変換 →
  iPad が HA の API を呼ぶ → 結果をスタックちゃんがしゃべる
- HA 側の出来事 (来客、洗濯終了など) をスタックちゃんが知らせる

自宅かどうかは「HA に届くか」で判定する (SSID だけに頼らない)。

## 会話の流れ

```
[M5 マイク] ─PCM─▶ [iPad STT] ─text─▶ [LLM] ─text─▶ [iPad TTS] ─PCM─▶ [M5 スピーカー]
                                       │
                         ┌─────────────┼──────────────┐
                         ▼             ▼              ▼
                   ローカル LLM   Cloudflare AI   Home Assistant
                   (常に使える)   (ネットあり)    (自宅のみ)
```

- 発話区間の検出: 最初はボタン/タッチで「押して話す」。慣れたら VAD (無音検出)
  で自動化する。
- 音声フォーマット: 16 kHz / 16 bit / モノラル PCM を WebSocket
  のバイナリフレームで送る。帯域が問題になったら Opus を検討する。
- しゃべっている間は M5 が音量から口パクを作る。表情は LLM の応答に付けた タグ
  (例: `[happy]`) か、Wasm 側のロジックで決める。

## Wasm でスタックちゃんの挙動を制御する

スタックちゃんの「性格」や「しぐさ」を、ファームウェアを焼き直さずに変えたい。
そのために M5 に Wasm ランタイムを入れ、挙動の一部を Wasm に任せる。

- M5 は **ホスト関数** (顔を変える、首を動かす、画像を出す、しゃべる、ログ…) を
  Wasm に公開する。
- Wasm は `init` / `on_tick` / `on_event` (タッチ、ボタン、発話開始/終了、
  受け取ったテキストなど) を export する。
- Wasm と画像は **HTTP API でアップロード**して差し替えられる。ブラウザからでも
  iPad からでも同じ API を叩く。
- 不正な Wasm で起動不能にならないよう、前のバージョンを残してロールバック
  できるようにする。

API と ABI の詳細は [M5 ファームウェア](./m5-firmware) に書く。

### Ruby → Wasm

挙動は Ruby で書きたい。ただし CRuby を丸ごと Wasm にした ruby.wasm は数 MB
あり、M5 のメモリには載らない。そこで組み込み向けの小さな Ruby (mruby/c /
PicoRuby 系) を使う。

1. **VM の Wasm** (mruby/c 系 VM + スタックちゃん用ホスト関数のバインディング)
   を事前にビルドしておく。数百 KB 以下を目標にする。
2. iPad 上で Ruby ソースを **バイトコード (`.mrb`) にコンパイル**する。
   コンパイラ自体も Wasm にして iPad アプリ内の Wasm ランタイムで動かす。
3. VM の Wasm にバイトコードを埋め込んで **1 つの `behavior.wasm`** にする。
4. スタックちゃんへアップロードする。

M5 から見ればただの Wasm なので、Ruby 以外 (Rust、Zig、AssemblyScript など)
で書いた Wasm も同じ API に載る。詳細は [iPad アプリ](./ios-app)。

## Cloudflare AI

- iPad から自分の Cloudflare の Worker を呼び、Worker が Workers AI
  (LLM、必要なら Whisper などの STT、TTS) を呼ぶ。
- API トークンは iPad や M5 に置かず、Worker 側に置く。iPad → Worker
  の認証は別に用意する (アプリ固有の鍵など)。
- AI Gateway を挟んで、ログ・キャッシュ・レート制限をかける。
- Worker のコードは必要になったら `web/` 側 (Deno + Remix テンプレートの
  Cloudflare Workers 構成) に足す。

## 段階的な作り方

| フェーズ | ゴール                                                                  |
| -------- | ----------------------------------------------------------------------- |
| 0        | リポジトリ、構想ドキュメント (この文書)                                 |
| 1        | M5 が AP を立て、iPad とつながる。話しかけるとローカルだけで返事が来る  |
| 2        | M5 に Wasm ランタイム。Wasm と画像を API でアップロードして挙動が変わる |
| 3        | iPad で Ruby → Wasm を作ってアップロードできる                          |
| 4        | Wi-Fi 設定 (スキャン → 選択 → 接続)。同じ Wi-Fi で制御、Cloudflare AI   |
| 5        | Home Assistant 連携                                                     |

フェーズ 1 が「最低限の機能」。ここまでで、ネットの無い場所でも
スタックちゃんと話せる。

## 未決事項

- M5 の機種: CoreS3 (ESP32-S3、PSRAM 8 MB、マイク・カメラ内蔵) を第一候補。
  Core2 も対応するか。
- サーボの種類 (PWM の SG90 系か、シリアルサーボか)。
- マイクを M5 にするか iPad にするか (近くにいるなら iPad
  のマイクの方が音質は良い)。両方選べるようにするか。
- M5 の API の認証: AP のパスワードとは別に、初回ペアリングでトークンを
  発行するか。
- Wasm ランタイムの選定 (WAMR か wasm3 か)。
- Cloudflare 側で使うモデル。
- iPad が手元に無いとき、M5 が直接 Cloudflare を呼ぶ「単独モード」を作るか。
